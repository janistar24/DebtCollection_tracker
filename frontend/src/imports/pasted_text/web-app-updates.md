2. รวม SEARCH PAYMENT + RECORD PAYMENT
==================================================

ใช้หน้าเดิมที่ออกแบบไว้สำหรับ “ค้นหาเจ้าของยอดชำระ”
แต่เปลี่ยนชื่อหน้าเป็น:

“ตรวจสอบและบันทึกการชำระ”

ภายในหน้าให้มี 2 วิธีทำงานที่ชัดเจน:

TAB 1:
“ค้นหาจากยอดเงิน”

สำหรับกรณี:
เห็นเงินโอนเข้ามา แต่ยังไม่รู้ว่าเป็นของใคร

Workflow:
กรอกยอด
→ Search Candidate
→ ตรวจสอบกับระบบต้นทาง
→ เลือกผู้เสียภาษี
→ Confirm
→ บันทึก Payment

TAB 2:
“บันทึกการชำระ”

สำหรับกรณี:
รู้แล้วว่าใครเป็นผู้ชำระ
เช่น มาชำระเงินสดที่หน่วยงาน

Workflow:
Search ชื่อ / Owner Code
→ เลือกผู้เสียภาษี
→ เลือกประเภทภาษี
→ กรอกยอด
→ Payment Method
→ Receipt No. / Reference No.
→ Confirm

อย่าสร้างสองหน้าแยกกัน

==================================================

คง Edit Mode เดิม

ใน View Mode:
Column “หมายเหตุ” อ่านได้อย่างเดียว

เมื่อกด:
“แก้ไขข้อมูล”

Column “หมายเหตุ”
ต้องเปลี่ยนเป็น Editable Input / Text Area ภายในแถวทันที

พนักงานสามารถ:
- เพิ่มหมายเหตุ
- แก้หมายเหตุ
- ลบข้อความหมายเหตุ

ตัวอย่าง:
“เพิ่มป้ายหน้าร้าน”
“ลดพื้นที่ป้าย”
“เลิกกิจการ”
“ติดต่อช่วงบ่ายสะดวก”

เมื่อกด:
“บันทึกการแก้ไข”

ให้ Save หมายเหตุพร้อมข้อมูลอื่นของแถวนั้น

หากมีการแก้ยอดภาษี
ยังคง Require เหตุผลการเปลี่ยนแปลงตาม Design เดิม

Tags ใน Taxpayer Detail
สามารถนำข้อมูลสำคัญจากหมายเหตุนี้มาแสดงตาม Design เดิม

Report = ใช้ตรวจสอบข้อมูลและสร้างเอกสารทางการ

บนหน้าจอ Report สามารถคง:
Filter
Summary
Table
Visualization ที่จำเป็น

แต่ลด Visualization ที่ซ้ำกับ Dashboard

เน้น:
ตัวเลขสรุป
ตาราง
การตรวจสอบ
การเปรียบเทียบ
ความถูกต้องของข้อมูล

--------------------------------------------------
PRINT / EXPORT VIEW
--------------------------------------------------

เมื่อกด:
“พิมพ์รายงาน”
หรือ
“Export PDF”

ห้าม Print หน้าจอ Dashboard ตรง ๆ

ให้สร้าง Official Print Layout แยกต่างหาก

Design:
- พื้นหลังขาว 100%
- ตัวอักษรดำ
- ไม่มี Liquid Glass
- ไม่มี Shadow
- ไม่มีสีม่วง Pastel
- ไม่มี Sidebar
- ไม่มี Navigation
- ไม่มีปุ่ม
- ไม่มี Decorative Element
- ใช้เส้นตารางสีดำ/เทา
- Typography ภาษาไทยที่เป็นทางการ
- ใช้พื้นที่กระดาษอย่างมีประสิทธิภาพ

Header เอกสาร:
ชื่อหน่วยงาน
ชื่อรายงาน
ปีภาษี
วันที่ออกรายงาน
กลุ่มผู้รับผิดชอบ
ชื่อพนักงานผู้รับผิดชอบ

ตัวอย่างชื่อ:
“รายงานสรุปผลการติดตามและจัดเก็บภาษี ประจำปี 2569”

Summary:
ผู้เสียภาษีทั้งหมด
ชำระครบ
ยังไม่ชำระ
ชำระบางส่วน
ยอดภาษีทั้งหมด
รับชำระแล้ว
ยอดคงเหลือ

จากนั้นแสดงตารางรายละเอียด

Visualization ใน Print Report:
สามารถมีได้ แต่ต้องเป็น Print-Friendly

ใช้:
- Black / Gray
- Pattern / Label / Percentage
- เส้นขอบชัดเจน

Chart ต้องยังอ่านรู้เรื่องเมื่อ Print ขาวดำ

หลีกเลี่ยง Pie Chart ที่ต้องอาศัยสีเพื่อแยกข้อมูล

ถ้าต้องการ Visualization:
ใช้ Horizontal Bar Chart หรือ Progress Bar แบบขาวดำ
พร้อมตัวเลขกำกับโดยตรง

Footer:
เลขหน้า
วันที่พิมพ์
ชื่อผู้จัดทำ/ผู้รับผิดชอบ หากเหมาะสม

รองรับ:
Print
Export PDF
Export Excel

Excel เน้น Raw Table / Summary

==================================================
13. UX ACCESSIBILITY
==================================================

เนื่องจากผู้ใช้งานบางคนอาจไม่ถนัดเทคโนโลยี:

- อย่าใช้ Icon โดยไม่มีข้อความ
- Button สำคัญต้องมี Label ภาษาไทย
- Font Size ต้องอ่านง่าย
- Contrast ชัดเจน
- หลีกเลี่ยง Text สีเทาอ่อนเกินไป
- จำนวนเงินใช้ comma และ “บาท”
- จำนวนคนใช้คำว่า “ราย” เสมอ
- ใช้คำที่พนักงานเข้าใจ ไม่ใช้ Technical Term
- Action สำคัญต้องอยู่ตำแหน่งเดิมอย่างสม่ำเสมอ
- ไม่ซ่อน Function สำคัญไว้ใน Three-dot Menu
- Confirmation Message ต้องบอกชัดว่าจะเกิดอะไรขึ้น
- Table Header ต้องอ่านง่าย
- Click Target ต้องมีขนาดเหมาะสม

ตัวอย่าง:

ไม่ใช้:
“92”

ให้ใช้:
“ยังไม่ชำระ 92 ราย”

ไม่ใช้:
“32 ⚠️”

ให้ใช้:
