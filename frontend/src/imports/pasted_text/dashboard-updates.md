แก้ไขเฉพาะบางส่วนของ Web Application เดิม โดยห้าม Generate ใหม่ทั้งโปรเจกต์ และห้ามเปลี่ยน Design System เดิม

คงสไตล์เดิมทั้งหมด:
- Liquid Glass / Frosted Glass
- พื้นหลังสีขาว
- Accent สีม่วง Pastel / Lavender
- Typography ภาษาไทย
- Sidebar / Header / Spacing / Border Radius / Component Style เดิม
- Desktop-first
- เน้นใช้งานง่าย ลดงานซ้ำ และลดจำนวน Click

ให้แก้เฉพาะ 3 ส่วนต่อไปนี้

==================================================
1. แก้หน้า DASHBOARD / หน้าหลัก
==================================================

ให้คง Layout หลักของ Dashboard เดิม แต่แก้ Quick Menu และการ Visualize ข้อมูล

------------------------------
QUICK MENU
------------------------------

ลบ Quick Menu:
“เพิ่มผู้เสียภาษี”

เปลี่ยน Quick Menu ให้เหลือ 4 เมนูนี้เท่านั้น:

1. บันทึก Call Log
2. ค้นหายอดชำระ
3. บันทึกการชำระ
4. ดูรายงานวันนี้

ออกแบบเป็น Quick Action Card หรือ Compact Glass Button ที่กดง่าย
มี Icon ที่เข้าใจง่าย

ตัวอย่าง Icon:
- บันทึก Call Log → โทรศัพท์
- ค้นหายอดชำระ → Search / เงิน
- บันทึกการชำระ → Receipt / Payment
- ดูรายงานวันนี้ → Report / Document

ให้ Quick Menu อยู่ในตำแหน่งที่เห็นง่าย แต่ไม่แย่งความสำคัญจาก Task Dashboard

------------------------------
TAXPAYER PAYMENT STATUS VISUALIZATION
------------------------------

เดิมที่แสดงตัวเลขจำนวนผู้เสียภาษี:
- ชำระครบ
- ยังไม่ชำระ
- ชำระบางส่วน

ไม่ต้องการให้เป็น Text Card หลายกล่องอย่างเดียว

ให้เปลี่ยนเป็น Visualization ที่เห็นสัดส่วนได้ทันที

แนะนำให้ใช้:
Donut Chart

หัวข้อ:
“สถานะการชำระของผู้เสียภาษี”

แบ่งเป็น 3 ส่วน:
- ชำระครบ
- ชำระบางส่วน
- ยังไม่ชำระ

ตรงกลาง Donut แสดง:
“ผู้เสียภาษีทั้งหมด”
และจำนวนรวม

ด้านข้างหรือด้านล่างมี Legend พร้อมจำนวนและเปอร์เซ็นต์

ตัวอย่าง:
ชำระครบ 180 ราย 60%
ชำระบางส่วน 30 ราย 10%
ยังไม่ชำระ 90 ราย 30%

ใช้สี Pastel ที่สอดคล้องกับ Design System
หลีกเลี่ยงสีแดงสด
สถานะที่ต้อง Attention สามารถใช้ม่วงเข้ม / peach / soft rose ได้

Chart ต้อง Clickable:
เมื่อกดส่วน “ยังไม่ชำระ”
ให้ Filter Task List ด้านล่างเฉพาะคนที่ยังไม่ชำระ

------------------------------
TAX AMOUNT VISUALIZATION
------------------------------

เดิมมีข้อมูล:
ยอดภาษีทั้งหมด
รับชำระแล้ว
ยอดคงเหลือ

อย่าแสดงเป็นตัวเลขแยก Card จำนวนมากจนรก

ให้สร้าง Card ใหญ่ชื่อ:
“ภาพรวมการจัดเก็บภาษี”

ภายในแสดง:

ยอดภาษีที่ต้องจัดเก็บทั้งหมด
XXX,XXX บาท

ด้านล่างใช้ Horizontal Progress Bar / Stacked Progress Bar

แบ่งเป็น:
- รับชำระแล้ว
- ยอดคงเหลือ

เช่น:

ยอดทั้งหมด 1,000,000 บาท

[████████████████░░░░░░]

รับชำระแล้ว
700,000 บาท
70%

คงเหลือ
300,000 บาท
30%

ด้านล่างสามารถแยก Small Breakdown:
ภาษีที่ดินและสิ่งปลูกสร้าง
ภาษีป้าย

แต่ไม่ต้องทำ Chart ใหญ่สองอันแยกกัน

ให้สามารถ Toggle:
“รวมทั้งหมด”
“ภาษีที่ดินฯ”
“ภาษีป้าย”

เมื่อ Toggle แล้ว Progress Visualization เปลี่ยนตามประเภทภาษี

Goal:
ผู้ใช้ต้องมองเพียงครั้งเดียวแล้วรู้ว่า
“เก็บได้กี่เปอร์เซ็นต์แล้ว และยังเหลืออีกเท่าไร”

------------------------------
DASHBOARD PRIORITY
------------------------------

เรียง Visual Hierarchy:

1. วันนี้ต้องทำอะไร / Task สำคัญ
2. Quick Menu
3. ภาพรวมสถานะผู้เสียภาษี
4. ภาพรวมยอดเงิน
5. Task List รายบุคคล

Dashboard ไม่ควรเต็มไปด้วย Card ตัวเลขขนาดเท่ากันทั้งหมด

==================================================
2. แก้หน้า “ข้อมูลผู้เสียภาษีประจำปี”
==================================================

คง Table Structure เดิมทั้งหมด

ต้องการเพิ่ม Edit Mode ที่ชัดเจน

ด้านบน Table ให้มีปุ่ม:

“แก้ไขข้อมูล”

Default State:
VIEW MODE

ใน View Mode:
- ตารางอ่านอย่างเดียว
- ไม่มีปุ่มลบ
- ไม่มีแถวเพิ่ม
- ป้องกันการแก้ข้อมูลโดยไม่ตั้งใจ

เมื่อกด:
“แก้ไขข้อมูล”

เปลี่ยนเข้าสู่ EDIT MODE

แสดง Indicator เช่น:
“กำลังแก้ไขข้อมูลปีภาษี 2569”

และเปลี่ยนปุ่มเป็น:
“ยกเลิก”
“บันทึกการแก้ไข”

------------------------------
REMOVE TAXPAYER ROW
------------------------------

เมื่อเข้าสู่ Edit Mode

ให้ Column ใหม่ปรากฏทางด้านขวาสุดของ Table โดยทันที

เป็น Narrow Action Column

แต่ละแถวมีปุ่ม:
“-”

หรือ Icon ลบแบบ Minimal

ใช้สำหรับ:
นำผู้เสียภาษีรายนั้นออกจากรายการของปีภาษีปัจจุบัน
ในกรณีที่ปีนี้ไม่มีการคิดภาษีแล้ว

IMPORTANT:
ไม่ควร Delete ตัว Taxpayer ออกจาก Database ทั้งหมด

การลบในหน้านี้หมายถึง:
“นำออกจากรายการผู้เสียภาษีของปีภาษีนี้”

ข้อมูลประวัติปีเก่ายังต้องอยู่

เมื่อกดลบ:
เปิด Confirmation Dialog

ตัวอย่าง:

“นำรายชื่อนี้ออกจากปีภาษี 2569?”

ชื่อ:
นาย ก.

ข้อความ:
“ข้อมูลปีภาษีที่ผ่านมาและข้อมูลประจำตัวผู้เสียภาษีจะไม่ถูกลบ”

ปุ่ม:
ยกเลิก
ยืนยันนำออก

------------------------------
ADD TAXPAYER INLINE ROW
------------------------------

เมื่ออยู่ใน Edit Mode

ให้เพิ่มแถวพิเศษที่ด้านล่างสุดของ Table

แถวนี้เป็น Inline Add Row

ลักษณะ:
Glass / Light Purple Highlight
แตกต่างจากแถวข้อมูลปกติเล็กน้อย

มีช่อง Input ตาม Column ที่จำเป็น

เช่น:
รหัสเจ้าของทรัพย์สิน
ชื่อ-นามสกุล / บริษัท

ภาษีที่ดินและสิ่งปลูกสร้าง:
ยอดปีปัจจุบัน

ภาษีป้าย:
ยอดปีปัจจุบัน

หมายเหตุ

ไม่ต้องให้กรอก:
ยอดปีก่อน
เพิ่ม/ลดจากปีก่อน

เพราะระบบต้องดึง/คำนวณเอง

เมื่อกรอก Owner Code:
ระบบควร Search ข้อมูล Taxpayer เดิมก่อน

กรณีพบ Taxpayer อยู่ใน Database:
Auto-fill:
ชื่อ
ข้อมูลพื้นฐาน
ยอดปีก่อน

พนักงานกรอกเฉพาะยอดของปีนี้และหมายเหตุ

กรณีไม่พบ Taxpayer:
แสดงข้อความ:
“ไม่พบข้อมูลผู้เสียภาษีรายนี้”

มี Action:
“เพิ่มข้อมูลผู้เสียภาษีรายใหม่”

Action นี้ค่อย Link ไปหน้า Add Taxpayer เดิม

ดังนั้น Inline Row นี้ไม่ควรบังคับให้พนักงานกรอกข้อมูล Personal Profile ใหม่ทั้งหมด

------------------------------
TABLE EDITING EXPERIENCE
------------------------------

ใน Edit Mode:

เมื่อยอดใหม่แตกต่างจากเดิม:
ให้ Highlight Cell เบา ๆ

และก่อน Save ต้องกรอก “เหตุผล/หมายเหตุ”

สามารถใช้ Popover / Small Modal สำหรับเหตุผล
ไม่ต้องเปิดหน้าใหม่

ระบบคำนวณ:
ยอดปีก่อน
ส่วนต่าง
เพิ่ม / ลด

อัตโนมัติ

เมื่อกด “บันทึกการแก้ไข”
ให้ Confirm ก่อน Save

หลัง Save:
กลับสู่ View Mode

3. แก้หน้า “รายละเอียดผู้เสียภาษี”
==================================================

คงหน้า Profile / Case Detail เดิม

เพิ่ม Section ใต้ Profile Header:

“TAGS / ข้อมูลสำคัญ”

Tags เหล่านี้เกิดจากข้อความ “หมายเหตุ”
ที่พนักงานกรอกในหน้า
“ข้อมูลผู้เสียภาษีประจำปี”

ตัวอย่างหมายเหตุ:

“ร้านปิดกิจการบางช่วง”
“เพิ่มป้ายหน้าร้าน”
“โทรช่วงบ่ายสะดวก”
“เปลี่ยนเจ้าของกิจการ”
“ลดพื้นที่ป้าย”

ให้นำข้อความสำคัญจาก Note มาแสดงเป็น Tags ใต้ข้อมูล Profile

ตัวอย่าง:

[ เพิ่มป้าย ]
[ ติดต่อช่วงบ่าย ]
[ เปลี่ยนเจ้าของกิจการ ]

ใช้ Tag / Chip Style แบบ Pastel
สีอ่อน
อ่านง่าย
ไม่เกิน 1–2 บรรทัด

IMPORTANT:
อย่าแสดง Note ทั้งย่อหน้าเป็น Tag เดียว

ให้ออกแบบ UI รองรับการ Extract keyword / short phrase จาก Note

แต่ใน Prototype ยังไม่จำเป็นต้องทำ AI จริง
สามารถจำลอง Tag ที่ได้จาก Note

มี Tooltip หรือ Click Tag ได้:
เมื่อกด Tag
แสดงข้อความหมายเหตุต้นฉบับและปีภาษีที่บันทึก

ตัวอย่าง:

Tag:
“เพิ่มป้าย”

Click →

ปีภาษี 2569
หมายเหตุ:
“เพิ่มป้ายหน้าร้านอีก 1 ป้าย ทำให้ยอดภาษีเพิ่มขึ้น”

------------------------------
TAG PRIORITY
------------------------------

Tags ใหม่กว่าควรแสดงก่อน

ถ้ามี Tag เดิมซ้ำหลายปี:
ไม่ต้องแสดงซ้ำหลาย Tag

สามารถแสดง:
[ เพิ่มป้าย ]
และ Tooltip ระบุว่าพบในปี 2568, 2569

หาก Tag เยอะ:
แสดง 4–5 Tag แรก
แล้วมี:
“+3 เพิ่มเติม”
