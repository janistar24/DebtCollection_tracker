เพิ่มหน้าใหม่ใน Web Application เดิม โดยห้ามเปลี่ยน Design System, Sidebar, Header, Typography, สี และ Layout Style ของหน้าที่ออกแบบไว้แล้ว

ให้ใช้ Visual Style เดิม:
- Liquid Glass / Frosted Glass
- พื้นหลังสีขาว
- Accent สีม่วง Pastel / Lavender
- สะอาดตา
- ใช้งานง่าย
- ภาษาไทยทั้งหมด
- Desktop-first
- เน้นลดขั้นตอนการทำงานของพนักงาน

ชื่อเมนู:
“ค้นหายอดชำระ”

เพิ่มเมนูนี้ใน Sidebar ของระบบเดิม

========================================
PAGE : ค้นหายอดชำระ
========================================

PURPOSE:

หน้านี้ใช้ในกรณีที่พนักงานพบ “ยอดเงินที่ชำระเข้ามา”
จากระบบรับชำระหรือระบบอื่น แต่ยังไม่ทราบแน่ชัดว่า
ยอดเงินดังกล่าวเป็นของผู้เสียภาษีรายใด

Workflow จริงคือ:

พบยอดเงิน
→ พิมพ์จำนวนเงิน
→ ระบบค้นหาผู้เสียภาษีที่มียอดค้างตรงหรือใกล้เคียง
→ พนักงานตรวจสอบข้อมูลเพิ่มเติมจากระบบต้นทาง
→ Search ผู้เสียภาษี
→ เลือกรายการที่ถูกต้อง
→ ยืนยันว่าเงินเป็นของผู้เสียภาษีรายนั้น
→ บันทึกการชำระ
→ ระบบอัปเดตยอดคงเหลือและสถานะ

IMPORTANT:
ระบบนี้เป็น Assisted Matching
ไม่ใช่ Auto Matching

ห้ามให้ระบบตัดสินอัตโนมัติว่าเงินเป็นของใคร
พนักงานต้องเป็นผู้ตรวจสอบและกดยืนยัน

========================================
SECTION 1 : SEARCH PAYMENT AMOUNT
========================================

ด้านบนของหน้าให้มี Header:

“ค้นหาเจ้าของยอดชำระ”

Subtext:
“กรอกยอดเงินที่ได้รับ เพื่อค้นหารายการภาษีที่มียอดตรงหรือใกล้เคียง”

สร้าง Search Card ขนาดเด่นแต่ไม่ใหญ่เกินไป

มี Input:

ยอดเงินที่ได้รับ
[ 101.00 ] บาท

ปุ่ม Primary:
“ค้นหายอด”

สามารถกด Enter เพื่อ Search ได้ทันที

มี Advanced Filter แบบพับ/ขยายได้ โดยไม่รบกวนการ Search หลัก:

- ปีภาษี
- ประเภทภาษี
  • ทั้งหมด
  • ภาษีที่ดินและสิ่งปลูกสร้าง
  • ภาษีป้าย

- กลุ่มผู้รับผิดชอบ
- ชื่อ / รหัสเจ้าของทรัพย์สิน

สำหรับพนักงานผู้ดูแลภาษี
Default ให้ค้นหาภายในกลุ่มที่ตนรับผิดชอบก่อน

Director / Admin สามารถค้นหาทุกกลุ่มได้

SECTION 4 : CONFIRM PAYMENT
========================================

เมื่อพนักงานกด
“ยืนยันว่าเป็นรายนี้”

เปิด Modal:

“ยืนยันการชำระ”

แสดงข้อมูลด้านบน:

ผู้เสียภาษี:
นาย B

ประเภทภาษี:
ภาษีป้าย

ปีภาษี:
2569

ยอดที่ต้องชำระ:
100.68 บาท

ยอดเงินที่พบ:
101.00 บาท

ส่วนต่าง:
+0.32 บาท

จากนั้นให้พนักงานกรอก:

วันที่ชำระ

ช่องทางการชำระ:
- โอน
- เงินสด

ถ้าเลือก “โอน”
แสดง:
เลขอ้างอิงการชำระ (ถ้ามี)

ถ้าเลือก “เงินสด”
แสดง:
เลขที่ใบเสร็จ (Receipt No.)

สามารถมี Receipt No. ได้เพื่อรองรับการชำระเงินสดและการตรวจสอบย้อนหลัง

แสดง Payment Calculation อัตโนมัติ:

ยอดเงินที่ได้รับ       101.00 บาท
ยอดภาษีคงเหลือ        100.68 บาท
นำไปตัดยอด             100.68 บาท
ส่วนต่าง                  0.32 บาท

พนักงานไม่ต้องคำนวณเอง

ห้ามทำให้ยอดคงเหลือเป็นค่าติดลบ

ปุ่ม:
“ยกเลิก”
“ยืนยันการชำระ”

ใช้ Confirmation ก่อน Save เพราะเป็นข้อมูลทางการเงิน

========================================
EMPTY / MULTIPLE RESULTS
========================================

กรณีค้นหาแล้วไม่พบ:

แสดง Empty State:

“ไม่พบยอดภาษีที่ตรงหรือใกล้เคียง”

มีทางเลือก:
“ค้นหาจากชื่อหรือรหัสเจ้าของทรัพย์สิน”

ห้ามบังคับให้พนักงานสร้าง Payment ที่ไม่มีเจ้าของทันที

กรณีพบหลายคนยอดเท่ากัน:

แสดงทุกราย

ตัวอย่าง:
“พบ 8 รายการที่มียอด 101.00 บาท”

ให้พนักงานเป็นผู้ตรวจสอบ

ห้ามเลือก Candidate แรกให้อัตโนมัติ

========================================
UX PRIORITY
========================================

หน้านี้ถูกสร้างขึ้นเพื่อแก้ Pain Point:

“เห็นยอดเงินเข้า แต่ไม่รู้ว่าเป็นของผู้เสียภาษีรายไหน”

ดังนั้นพนักงานควรสามารถทำงานตามลำดับง่าย ๆ:

พิมพ์ยอด
→ เห็น Candidate
→ ตรวจสอบ
→ ยืนยัน
→ เสร็จ

ไม่ควรต้องเปิดหลาย Modal
ไม่ควรต้องกรอกข้อมูลเดิมซ้ำ
ไม่ควรให้พนักงานคำนวณส่วนต่างเอง

Search Amount ต้องเป็น Visual Priority อันดับแรกของหน้า

ใช้ Table ที่อ่านง่าย
ใช้ Pastel Purple Highlight สำหรับ Selected Candidate
ใช้ Status Badge ที่ชัดเจน
ใช้ Drawer สำหรับดูรายละเอียด Candidate
ใช้ Modal เฉพาะตอน Confirm Payment

รักษา Design System เดิมของ Web Application ทั้งหมด
และห้าม Redesign หน้าที่ Generate ไว้ก่อนหน้านี้
