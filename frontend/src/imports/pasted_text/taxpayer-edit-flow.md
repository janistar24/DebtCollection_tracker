แก้ไขเฉพาะ Feature “แก้ไขข้อมูล” ในหน้า
“ข้อมูลผู้เสียภาษีประจำปี”
และแก้ Business Rule ของ Owner Code

ห้าม Generate หน้าใหม่
ห้ามเปลี่ยน Design System หรือ Layout หลักเดิม

==================================================
1. แก้ Flow การเพิ่มรายชื่อในข้อมูลผู้เสียภาษีประจำปี
==================================================

ยกเลิก Flow เดิมที่ให้พนักงานกรอก Owner Code
เพื่อเพิ่มผู้เสียภาษีเข้าในตารางประจำปี

แนวคิดใหม่คือ:

ผู้เสียภาษีต้องถูกสร้างและมีข้อมูลอยู่ในระบบก่อนแล้ว

หน้า “ข้อมูลผู้เสียภาษีประจำปี”
มีหน้าที่เพียงเลือกผู้เสียภาษีที่มีอยู่
เข้ามาอยู่ในรายการของปีภาษีปัจจุบัน

--------------------------------------------------
EDIT MODE
--------------------------------------------------

เมื่อกดปุ่ม:

“แก้ไขข้อมูล”

ให้เข้าสู่ Edit Mode ตาม Design เดิม

และแสดงแถว:

“+ เพิ่มรายการ”

ที่ด้านล่างสุดของตาราง

--------------------------------------------------
ADD NEW ROW
--------------------------------------------------

ในแถวเพิ่มรายการใหม่

Column “ชื่อ - ชื่อสกุล”
ให้เป็น Searchable Dropdown / Combobox

ไม่ใช้ Owner Code เป็น Input

Placeholder:

“ค้นหาและเลือกผู้เสียภาษี”

เมื่อ Click Dropdown
แสดงรายชื่อผู้เสียภาษีที่มีอยู่ในฐานข้อมูล
และสามารถพิมพ์ Search ได้

ค้นหาได้จาก:
- ชื่อ
- นามสกุล
- ชื่อบริษัท

ตัวอย่าง Dropdown:

นายกรกน สำลีสัน
บุคคลธรรมดา

นายสมชาย ใจดี
บุคคลธรรมดา

บริษัท ตัวอย่าง จำกัด
นิติบุคคล

--------------------------------------------------
หลังเลือกผู้เสียภาษี
--------------------------------------------------

เมื่อเลือกชื่อแล้ว

ให้ระบบ Auto-fill ข้อมูลที่มีอยู่โดยอัตโนมัติ

เช่น:
ชื่อ - นามสกุล
ประเภทบุคคล
ข้อมูลประจำตัวที่จำเป็น
ข้อมูลภาษีของปีก่อน หากมี

พนักงานไม่ต้องกรอกข้อมูลส่วนตัวซ้ำ

จากนั้นพนักงานกรอกเฉพาะข้อมูลของปีภาษีปัจจุบัน เช่น:

ภาษีที่ดินและสิ่งปลูกสร้าง
- จำนวนเงินปีปัจจุบัน

ภาษีป้าย
- จำนวนเงินปีปัจจุบัน

หมายเหตุ

ระบบคำนวณ:
- ยอดปีก่อน
- เพิ่ม/ลดจากปีก่อน

ให้อัตโนมัติ

จากนั้นกด:
“บันทึก”

Workflow ต้องสั้น:

กดแก้ไข
→ + เพิ่มรายการ
→ เลือกชื่อจาก Dropdown
→ ข้อมูลเดิม Auto-fill
→ กรอกยอดภาษีปีนี้
→ กรอกหมายเหตุถ้ามี
→ บันทึก

==================================================
2. DROPDOWN BEHAVIOR
==================================================

Dropdown ไม่ควรแสดงรายชื่อจำนวนมากทั้งหมดในครั้งเดียวจนรก

ให้เป็น Searchable Dropdown

เมื่อพิมพ์ เช่น:

“กรก”

ระบบแสดง Candidate ที่ตรงกับคำค้นหา

แต่ละ Candidate แสดงอย่างน้อย:

ชื่อ - นามสกุล
ประเภทบุคคล

สำหรับบุคคลธรรมดาที่มี Owner Code
สามารถแสดง Owner Code เป็น Secondary Text ขนาดเล็กได้

ตัวอย่าง:

นายกรกน สำลีสัน
ก-715/8785 · บุคคลธรรมดา

IMPORTANT:
Owner Code มีไว้ช่วยแยกบุคคล
แต่ไม่ใช่สิ่งที่พนักงานต้องกรอกในขั้นตอนนี้

--------------------------------------------------
ป้องกันการเพิ่มซ้ำ
--------------------------------------------------

ถ้าผู้เสียภาษีรายนั้นมีอยู่ในรายการของปีภาษีที่กำลังแก้ไขแล้ว

ให้ Disable รายชื่อนั้นใน Dropdown
หรือแสดง:

“มีอยู่ในปีภาษี 2569 แล้ว”

ห้ามเพิ่ม Duplicate

==================================================
3. กรณีไม่พบชื่อใน Dropdown
==================================================

หาก Search แล้วไม่พบผู้เสียภาษี

แสดง Empty State:

“ไม่พบผู้เสียภาษีในระบบ”

พร้อม Action:

“+ เพิ่มผู้เสียภาษีรายใหม่”

เมื่อกดจึงค่อยไปยัง Form:
“เพิ่มผู้เสียภาษีรายใหม่”

หลังสร้างสำเร็จ
ควรสามารถกลับมายังหน้าข้อมูลประจำปี
และเลือกรายชื่อที่เพิ่งสร้างได้

==================================================
4. OWNER CODE — ใช้เฉพาะบุคคลธรรมดา
==================================================

แก้ Business Rule ให้ชัดเจน:

Owner Code แบบถอดรหัสจากชื่อและนามสกุล
ใช้เฉพาะ:

“บุคคลธรรมดา”

สำหรับ:

“นิติบุคคล / บริษัท”

ห้าม Generate Owner Code ด้วยกฎนี้

ชื่อบริษัทไม่ถูกนำมาถอดรหัส

ดังนั้นเมื่อประเภทบุคคล = บริษัท / นิติบุคคล

ไม่ต้องแสดง Generated Owner Code

และห้ามนำคำว่า:
บริษัท
ห้างหุ้นส่วน
จำกัด
หรือชื่อบริษัท

มาคำนวณ Owner Code

==================================================
6. OWNER CODE GENERATION
==================================================

สำหรับบุคคลธรรมดา:

รูปแบบ:

[พยัญชนะตัวแรกของชื่อ]-[เลข 3 หลักจากชื่อ]/[เลข 4 หลักจากนามสกุล]

ตัวอย่าง:

นายกรกน สำลีสัน

ไม่นำ “นาย” มาคำนวณ

ชื่อจริง:
กรกน

พยัญชนะตัวแรก:
ก

ใช้เป็น Prefix:

ก-

พยัญชนะหลังจากนั้น:
ร
ก
น

แปลงตาม Mapping Table
และสร้าง Numeric Code 3 หลัก

จากนั้นนามสกุล:
สำลีสัน

ข้ามสระ วรรณยุกต์ และอักขระที่ไม่ใช่พยัญชนะ
นำพยัญชนะตามกฎที่กำหนดมาสร้างรหัส 4 หลัก

ถ้าจำนวนพยัญชนะที่ต้องใช้ไม่ครบ
เติม 0 ด้านท้าย

ถ้ามีพยัญชนะเกินจำนวนที่กำหนด
ไม่ต้องนำตัวที่เกินมาคำนวณ

==================================================
7. IMPORTANT UX DISTINCTION
==================================================

ต้องแยก 2 Action นี้ออกจากกันให้ชัด:

ACTION A:
“เพิ่มผู้เสียภาษีรายใหม่”

หมายถึง:
สร้างบุคคล/บริษัทใหม่เข้าสู่ฐานข้อมูลหลัก

ACTION B:
“เพิ่มรายการในปีภาษี”

หมายถึง:
เลือกผู้เสียภาษีที่มีอยู่แล้ว
เข้ามาอยู่ในรายการของปีภาษีปัจจุบัน

ห้ามให้พนักงานกรอก Personal Information ซ้ำใน Action B

เป้าหมายคือ:

ข้อมูลคน
กรอกครั้งเดียว

ข้อมูลภาษี
เปลี่ยนตามแต่ละปี

เพื่อช่วยลดการกรอกข้อมูลซ้ำของพนักงาน
